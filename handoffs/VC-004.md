# VC-004 — First working application slice

Recorded 2026-09-23. Objective: turn the approved architecture/UI direction into a usable local foundation. Status: implemented in read-only preview with partial verification; full phase acceptance remains open. Dependencies and authoritative status are in `plan.md`.

## Repository and changes

This application folder has no Git repository, branch or checked commit. No automatic Git initialization, commit, push or publication occurred. Git observations were tested in separate temporary synthetic repositories. Existing planning documents were preserved and updated for current reality.

Added one locked TypeScript package, React UI, Fastify service, fixed Windows folder chooser, read-only filesystem/Git helpers, deterministic handoff generator, constrained connection probe, build/launch scripts and 21 integration/security tests. No database, native credential library, hosted service or coding-agent controller was introduced.

## Completed work

- Built neutral/sage light/dark UI with workspace navigation, task forms, outcome reporting, context inspector, connections and handoff review. Screens use actual service state rather than seeded demonstration data.
- Paired loopback session, exact Host/Origin validation, content-route authentication, single-use bootstrap, limited request/file sizes, restrictive CSP and application-owned static asset allowlist.
- Read-only folder grants reject unsupported paths, directory links and multiply-linked context files. The native chooser has a path-entry fallback and never bypasses execution policy.
- Local Git status uses fixed read-only arguments, bounded output and disabled helpers. No remote API, commits or tests run against user projects. Redirected Git metadata is unavailable pending an explicit grant design.
- Strict task draft schemas; user/agent-reported outcomes stay separate from app-observed Git metadata. Generated prompts explicitly name context files and require repository reconciliation before work.
- Session-only key entry, clearing and cancellation. Reviewed synthetic connection probe has HTTPS/DNS restrictions, no redirects and bounded response/time. Real endpoint compatibility is unconfirmed.
- Updated README, product direction, actual codebase, architecture decisions, operations and task statuses.

## Decisions and unresolved items

- Keep the first slice read-only until stale-write and recovery behavior is proven.
- Use installed Node 22.21.0 for this verified slice; Node 24 and clean-machine packaging remain separate qualifications.
- Keep endpoint keys in service memory. Corporate vault restrictions do not block the manual workflow. Durable non-secret profiles/drafts will be separate from keys.
- Tab-scoped session storage holds only the expiring loopback capability to support refresh. Strict CSP/text-only content mitigate, but do not eliminate, same-origin script compromise. No inference key or project content is stored there.
- Exact endpoint/model/dialect, company policy, native chooser compatibility, license and public name remain unresolved.
